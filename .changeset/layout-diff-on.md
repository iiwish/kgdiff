The Rust crate `kgdiff-layout` carries a layout from one version of a graph to the next through their diff: `layout_diff_on(&diff, &previous, &options)` lays the diff out on the previous version's map, and `layout_after(&diff, &layout, &options)` gives the after version the positions of its diff without computing any (RFC 0003, part 1). Every node the previous layout places stays exactly where it is, whether it continues or was removed and under whatever id it has now, and only the new nodes are placed, clear of the removed ones; going from a version to the next one, and from either to their diff, moves no node. Laying the next version out with `layout_graph` and the previous positions as pins gives that only when no id changes: a node that continues under another id is placed again, and an id given to another node pins that node where the old one was. Both functions are held to the `kgdiff.layout` bytes of the same pins written by hand on every case of the conformance corpus. A pin of the caller wins over the previous layout; scope `Changes` and strategy `Union` are `invalid-input`, and so is, for `layout_after`, a layout that does not place every node of the after version. The functions are experimental for one minor release, and `@kgdiff/layout` has no counterpart. The embedding guide and its example (`crates/kgdiff-report/examples/embedding.rs`) now use them.
