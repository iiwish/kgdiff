The payload of an HTML report has a JSON Schema: `schema/report.v1.json` describes `kgdiff.report` version 1 (`format`, `version`, the diff, packed or not, the optional `layout` of version 1 or 2, `meta` and the optional `view`), so an application that makes or reads reports can validate them as it can graphs, diffs and deltas. Members of `view` the schema does not name are allowed: later minor versions add optional ones, and viewers ignore those they do not know. The schema and `schema/layout.v2.json`, the layout document of kgdiff's Rust engine it refers to, are exported as `@kgdiff/core/schema/report.v1.json` and `@kgdiff/core/schema/layout.v2.json` (`layout.v2.json` was in the package already, without an export). In Rust, the `kgdiff-report` crate takes the layout of a report from its caller (RFC 0003, part 2): `report_payload_with` and `build_report_html_with` take a `ReportLayout`, which is `Default` (the layout of the default options, what `report_payload` and `build_report_html` keep writing, byte for byte), `Given(&layout)` (a layout the application has already, checked against the diff and refused with `invalid-input` when it places a node the diff does not have, or has scope `all` and leaves one out) or `None` (no layout: the viewer lays the diff out when the report opens). What `kgdiff` writes does not change.
